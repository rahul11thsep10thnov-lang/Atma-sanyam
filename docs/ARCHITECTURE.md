# Architecture

## Overview

```
Mobile app (Expo)                 Admin console (Next.js)
  │  HTTPS, Bearer user token        │  browser ⇄ Next.js server (httpOnly cookie)
  │  /v1/*                           │  Next.js server → API with Bearer admin token
  ▼                                  ▼  /admin/v1/*
┌─────────────────────────────────────────────────────┐
│ FOCUS API  (backend/, Express 5 + TypeScript)        │
│  • validation (zod) • auth (opaque hashed tokens)    │
│  • RBAC per route • rate limits • audit log         │
└───────────────┬───────────────────────┬─────────────┘
                ▼                       ▼
          PostgreSQL              Expo Push API → APNs / FCM
         (Drizzle ORM,            Resend (password-reset email)
          SQL migrations)
```

Design choices:

- **One API, no microservices.** A single Express service serves both the app (`/v1`) and the
  console (`/admin/v1`). Cheap to host, easy to reason about.
- **The mobile app never talks to the database** and ships no secrets. Everything it knows is
  a public API URL (`EXPO_PUBLIC_API_URL`).
- **The admin browser never holds the admin token.** Next.js stores it in an httpOnly,
  `SameSite=Strict` cookie and forwards requests server-side
  (`admin/src/app/api/backend/[...path]/route.ts`).
- **Authorization lives only in the API.** The console hides buttons for convenience; every
  admin route re-checks the permission (`backend/src/middleware/auth.ts`).
- **Offline-first app.** Remote config is cached, analytics are queued, and with no server
  configured the app runs exactly as it did before the backend existed.

## Database schema (PostgreSQL)

| Table | Purpose | Key columns |
|---|---|---|
| `users` | App accounts (optional) | `id uuid`, `email unique`, `password_hash` (scrypt), `display_name`, `status active\|deactivated`, `created_at`, `last_seen_at` |
| `user_sessions` | App sign-ins | `user_id → users (cascade)`, `token_hash unique` (SHA-256), `expires_at` (30-day sliding), `last_used_at` |
| `password_reset_codes` | Forgot-password codes | `user_id → users (cascade)`, `code_hash`, `attempts` (max 5), `expires_at` (15 min), `used_at` |
| `admins` | Console accounts | `email unique`, `name`, `password_hash`, `role_key → roles`, `status`, `failed_login_count`, `locked_until`, `last_login_at` |
| `admin_sessions` | Console sign-ins | `admin_id → admins (cascade)`, `token_hash unique`, `expires_at` (12 h absolute) |
| `roles` | `super_admin`, `admin`, `editor` | `key`, `name`, `description` |
| `permissions` | 16 permission keys | `key`, `description` |
| `role_permissions` | Role → permission matrix | `(role_key, permission_key)` PK |
| `categories` | Library hierarchy | `id` (slug, e.g. `nature-mountains-himalayas`), `name`, `parent_id → categories`, `sort_order` |
| `content` | Library images | `title`, `category_id`, `subcategory_id`, `tags text[]` (GIN index), `thumbnail_url`, `medium_url`, `full_url`, **`source`, `creator`, `license`, `attribution_required`, `attribution_text`** (mandatory rights metadata), `status draft\|published`, `popularity`, `published_at`, `created_by/updated_by → admins` |
| `app_settings` | Remote config (JSON per key) | `key` (`maintenance`, `app_version`, `feature_flags`, `texts`, `session`), `value jsonb`, `updated_by` |
| `devices` | Installs + push tokens | `install_id unique` (random per install), `user_id → users (set null)`, `platform`, `app_version`, `push_token`, `push_enabled`, `last_seen_at` |
| `notifications` | Push campaigns + history | `title`, `body`, `target jsonb` (`all`/`signed_in`/`platform`/`users`), `status draft\|sending\|sent\|failed`, recipient/success/failure counts, `error`, `created_by`, `sent_at` |
| `events` | Product analytics | `name`, `install_id`, `user_id (set null on delete)`, `platform`, `app_version`, `screen`, `content_id`, `properties jsonb`, `occurred_at` |
| `audit_logs` | Every console change | `admin_id`, `action`, `entity_type`, `entity_id`, `details jsonb`, `created_at` |

Migrations live in `backend/drizzle/*.sql`. Change `schema.ts`, run `npm run db:generate`,
commit the new SQL, and it's applied by `npm run db:migrate` (the Docker image runs it on start).
Roles/permissions are re-synced from `backend/src/database/rbac.ts` on every migrate.

### Roles & permissions

| Permission | Super Admin | Admin | Editor |
|---|:-:|:-:|:-:|
| dashboard:read | ✓ | ✓ | ✓ |
| content:read / write / publish | ✓ | ✓ | ✓ |
| content:delete | ✓ | ✓ | — |
| users:read / write / delete | ✓ | ✓ | — |
| settings:read / write | ✓ | ✓ | — |
| notifications:read / send | ✓ | ✓ | — |
| analytics:read | ✓ | ✓ | — |
| audit:read | ✓ | ✓ | — |
| admins:read / write | ✓ | — | — |

Safeguards: you can't change your own role/status or delete yourself, and the last active
Super Admin can't be demoted, deactivated or deleted.

## Security model

- **Passwords:** scrypt (N=2¹⁵, r=8, p=1, 16-byte salt) from Node's standard library; parameters are
  stored with each hash. Admins need ≥12 chars with upper/lower/digit; app users ≥8.
- **Sessions:** 256-bit random opaque tokens; only SHA-256 hashes are stored, so a DB leak doesn't
  leak sessions. Logout, password change, role change, deactivation and deletion revoke sessions
  immediately. App tokens live in the iOS Keychain / Android Keystore (expo-secure-store,
  excluded from device backups).
- **Brute force:** per-IP+email rate limits on every sign-in/reset endpoint; admin accounts lock for
  15 min after 5 failures; login timing is equalised for unknown emails; reset responses never
  reveal whether an email exists.
- **Authorization:** `requireAdmin` + `requirePermission(...)` on every admin route; user tokens are
  rejected on admin routes and vice versa (separate tables).
- **Input:** every body/query/param validated with zod; JSON body limit 100 KB; LIKE wildcards
  escaped; image URLs must be `https://` in production.
- **Transport & headers:** HTTPS terminated by the host; helmet security headers; CORS allow-list
  (empty in production — the app and console don't need it); admin responses `no-store`; console
  sends `X-Frame-Options: DENY`, `frame-ancestors 'none'`, HSTS, `noindex`.
- **Admin console:** token only in an httpOnly `SameSite=Strict` cookie; the proxy rejects cross-origin
  state-changing requests and validates path segments.
- **Logging:** method, route, status and timing only — no bodies, headers, tokens or query strings.
  Errors return generic messages; details stay in server logs.
- **Audit:** every admin change is recorded with who/what/when.
- **Privacy:** analytics are anonymous product events (no photos, no content from outside the app),
  can be turned off in Settings, and are unlinked from the person when their account is deleted.
  Old events are purged by `npm run cleanup` (default 395 days).
