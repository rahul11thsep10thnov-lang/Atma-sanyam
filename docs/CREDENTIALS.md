# What you need to provide

Nothing secret is committed to this repo. Everything below is entered in a host dashboard,
in EAS, or in a local `.env` file that git ignores.

## Accounts

| Account | Needed for | Where | Cost |
|---|---|---|---|
| **Expo** | Building/submitting the app, push notifications | expo.dev/signup | Free tier (paid plans = faster builds) |
| **Google Play Console** | Android release | play.google.com/console | $25 once |
| **Apple Developer Program** | iOS release | developer.apple.com/programs | $99/year |
| **Neon** (or any Postgres host) | Database | neon.tech | Free tier |
| **Render** (or Railway/Fly) | API hosting | render.com | Free tier; ~$7/mo Starter recommended |
| **Vercel** | Admin console hosting | vercel.com | Free (Hobby) |
| **Firebase** | Android push delivery (FCM) | console.firebase.google.com | Free |
| **Resend** *(optional)* | "Forgot password" emails | resend.com | Free tier |
| **Domain** *(optional, recommended)* | `api.` / `admin.` / privacy-policy URLs | any registrar | ~$10/yr |

## Values, where to get them, where to put them

### API (`backend/`) — host environment variables (Render → service → Environment)

| Variable | Where it comes from | Required |
|---|---|---|
| `DATABASE_URL` | Neon → project → *Connection string* (includes `?sslmode=require`) | ✅ |
| `NODE_ENV` | literally `production` | ✅ |
| `TRUST_PROXY` | `1` on Render/Railway/Fly | ✅ |
| `RESEND_API_KEY` | Resend → API Keys → Create | optional |
| `EMAIL_FROM` | an address on your Resend-verified domain, e.g. `FOCUS <no-reply@your-domain.com>` | with Resend |
| `EXPO_ACCESS_TOKEN` | expo.dev → Account settings → Access tokens | optional (push hardening) |
| `CORS_ORIGINS` | leave empty in production | — |
| `ADMIN_BOOTSTRAP_EMAIL` / `_PASSWORD` / `_NAME` | you choose; used **once** in the Render Shell to create the first Super Admin, don't store them permanently | once |

### Admin console (`admin/`) — Vercel → Project → Settings → Environment Variables

| Variable | Value |
|---|---|
| `API_URL` | Your API's public URL, e.g. `https://api.your-domain.com` |

### Mobile app — EAS environment variables (public values only)

Set with `eas env:create` (commands in DEPLOYMENT.md §4) for `preview` and `production`;
locally in `.env`:

| Variable | Value |
|---|---|
| `EXPO_PUBLIC_API_URL` | Your API's public URL |
| `EXPO_PUBLIC_PRIVACY_POLICY_URL` | Your privacy policy page (required by both stores) |
| `EXPO_PUBLIC_TERMS_URL` | Optional terms page |
| `EXPO_PUBLIC_SUPPORT_EMAIL` | Optional support address shown in Settings |

`EXPO_PUBLIC_*` values are compiled into the app and readable by anyone — never put secrets there.

### EAS project & store credentials

| Item | How | Where it ends up |
|---|---|---|
| EAS project ID | `eas init` | Written into `app.json → expo.extra.eas.projectId` (commit it) |
| Android upload keystore | Generated by EAS on first `eas build -p android` | Stored on EAS servers |
| FCM V1 service-account key (push) | Firebase → Project settings → Service accounts → *Generate new private key* | Upload via `eas credentials` → Android → Push Notifications |
| Google Play service-account key (auto-submit) | Google Cloud → IAM → Service accounts → Keys; grant it access in Play Console → Users & permissions | Save as `secrets/play-service-account.json` (git-ignored) and give its path to `eas submit` |
| iOS distribution certificate + provisioning profile | Created by EAS when you run `eas build -p ios` and sign in with your Apple ID | Stored on EAS servers |
| APNs push key | `eas credentials` → iOS → Push Notifications key (EAS can create it) | Stored on EAS servers |
| App Store Connect app record | Created by `eas submit -p ios` (or manually in App Store Connect) | — |

### Pages you must publish (URLs, not secrets)

| Page | Used by |
|---|---|
| **Privacy policy** | Both stores, app Settings, sign-up screen |
| **Account deletion request page** | Google Play "Data safety" (can simply explain the in-app option and give a support email) |
| Terms of use (optional) | App Settings |

## The one-step-at-a-time order

1. Create Neon DB → deploy API on Render with `DATABASE_URL` → create the Super Admin in the Shell.
2. Deploy the admin console on Vercel with `API_URL` → sign in.
3. `eas init` → set EAS env vars → `npm run build:android:preview` and install it to test.
4. Firebase key → `eas credentials` (push) → test a notification from the console.
5. Store accounts → production builds → submit (STORE_SUBMISSION.md).
