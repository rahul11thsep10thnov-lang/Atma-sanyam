# Target architecture: cinematic 2.5D story production

> Built as described, with the module names below. Details per subsystem:
> `2.5d-engine.md`, `shot-system.md`, `asset-system.md`, `local-ai.md`,
> `gpu-workers.md`, `character-continuity.md`, `render-pipeline.md`, and
> `../operations/`.

The Studio stops thinking "article → image → Ken Burns". It thinks:

```
Article → Story → Episode → Scene → Shot → Visual composition → Scene package
        → Depth + masks → Procedural 2.5D animation → Shot render → FFmpeg → Video
```

A **shot** is a structured visual scene made of depth-ordered layers. AI
generates the *assets* (pictures, masks, depth). Our own software controls
story, composition, continuity, depth, camera, acting, lighting,
environment, editing, audio, rendering and QC.

## 1. End-to-end flow

```
                    NEWS / pasted article
                            │
                 (existing) analysis, facts, safety
                            │
                 (existing) master script: scenes
                            │
                     EpisodeDirector ──────────── StudioEpisode
                            │
                      ShotDirector ─────────────── StudioShot[] per scene
                            │                       (shot type, purpose, camera,
                            │                        MotionRequirementAnalyzer)
               VisualCompositionPlanner ─────────── composition + ShotLayer[]
                            │                       (bg / mid / chars / props / fg, depth)
              Continuity: CharacterReference, LocationReference, PropReference
                            │
               AssetLibrary: REUSE ▸ MODIFY ▸ GENERATE
                            │
      ┌─────────── GPU queues (image-generation, segmentation, depth-generation, inpainting) ───────────┐
      │  LocalImageProvider   LocalSegmentationProvider   LocalDepthProvider   LocalInpaintingProvider  │
      │  (ComfyUI / internal inference API / procedural offline fallback)                               │
      └─────────────────────────────────────────────────────────────────────────────────────────────────┘
                            │
                      ScenePackage (manifest + files: layers, masks, depth, metadata)
                            │
              ┌──── 2.5d-render queue: Engine25D ────┐        ┌── i2v queue (optional) ──┐
              │ SceneLayerComposer · DepthEngine     │  needs │ LocalVideoProvider        │
              │ ParallaxRenderer · CameraMotionEngine│ ──────▶│ 3–5 s clip from first      │
              │ CharacterMotionEngine · Particles    │ motion │ frame of the 2.5D shot     │
              │ LightingEngine · ShadowEngine        │        └────────────┬──────────────┘
              │ FocusEngine · CinematicEffectsEngine │                     │
              └──────────────────┬───────────────────┘                     │
                                 └─────────────┬───────────────────────────┘
                                               ▼
                              shot_NNN.mp4 (standard profile, e.g. 1080×1920 @ 30)
                                               │
                         studio-render (FFmpeg): master visual (concat)
                                               │
              per language: narration/dialogue/ambience/music mix + subtitles + localized
              disclosure overlay  → story_<id>_<lang>.mp4   (visuals are NOT re-rendered)
                                               │

                                               │
                              admin approval → publish → app feed (VideoAsset)
```

## 2. Data model (new and extended)

```
StudioStory (productionMode: CLASSIC | CINEMATIC_25D)
  └─ StudioEpisode (episodeNumber, masterScriptId, renderProfile, master visual)
       └─ StudioScene (existing; + episodeId)
            └─ StudioShot (shotType, camera, composition, motion decision, status…)
                 ├─ ShotLayer[] (kind, zIndex, depth, placement, asset/mask refs, motion)
                 ├─ ScenePackage[] (versioned manifest + storage prefix)
                 └─ ShotRender[] (versioned shot_NNN.mp4, inputs hash, QC)
Asset (kind, role, reuseKey, status, placeholder flag) ─ AssetVersion[] (model, seed, prompt, params, licence)
CharacterReference · LocationReference · PropReference   (continuity, reusable across shots/episodes)
RenderProfile · AiModel (model registry + licence) · GpuWorker
GenerationJob (+ episodeId, shotId, assetId, queue, provider, model, gpuWorkerId, progress, cancel, timeout)
```

Camera, lighting, environment (particles), focus, effects and the
animation timeline are stored as validated JSON on the shot (one zod
schema, `engine25d/spec.ts`) rather than as separate tables: they are
always read and written together, they are versioned through the scene
package, and admins override them as a unit.

## 3. The 2.5D engine (`backend/src/studio/engine25d`)

Software renderer written in TypeScript. It writes raw frames straight
into FFmpeg and renders frames in parallel on worker threads. Every frame
is a pure function of `(manifest, seed, t)`, so renders are deterministic
and resumable.

| System | Module | Responsibility |
|---|---|---|
| 1 Layer compositor | `composite.ts` | Premultiplied-alpha compositing of image layers with affine transforms (scale, rotation, translation), opacity, masks/clipping, blend modes (normal, multiply, screen, add), bilinear sampling. |
| 2 Depth engine | `depth.ts` | Depth normalisation, Z placement, depth → parallax factor, depth → blur, depth → fog/haze, depth → particle placement, composite depth-map generation; per-pixel depth displacement for single-image backgrounds. |
| 3 Parallax | `depth.ts` + `frameRenderer.ts` | Per-layer transform from camera state and depth: horizontal, vertical, zoom (dolly) and orbit/perspective-shift parallax across multiple planes. |
| Camera | `camera.ts` | static, dolly in/out, pan, tilt, orbit, tracking, push in, pull out, handheld, rack focus, whip pan, slow zoom; cubic-bezier easing; seeded shake. |
| Character motion | `characterMotion.ts` | Rigged characters (cut-out parts with joints): breathing, blink, head turn, eye direction, sway, walk/run cycles, gestures, cloth/hair secondary motion. Single-image characters: whole-figure breathing and sway. |
| Environment | `particles.ts` | Deterministic, analytic particle systems (rain, snow, fog, mist, smoke, dust, steam, fire, sparks, leaves, water, crowds, traffic, birds, insects). |
| Lighting | `lighting.ts` | Ambient + light sources (sun, moon, streetlight, headlights, police lights, fire, neon, interior, window, train light), flicker and movement; per-layer light response. |
| Shadows | `frameRenderer.ts` (`drawShadows`) | Contact shadows and projected cast shadows from layer alpha, driven by the dominant light (direction, softness, opacity, movement). |
| Focus | `focus.ts` | Depth of field, rack focus, focus transitions; precomputed blur levels per layer. |
| Effects | `effects.ts` | Film grain, vignette, bloom/glow, lens flare, chromatic aberration, colour grading, haze, motion blur, camera shake. |

## 4. Local AI

`localai/types.ts` defines `LocalImageProvider`, `LocalSegmentationProvider`,
`LocalDepthProvider`, `LocalInpaintingProvider`, `LocalVideoProvider`
(optional). Adapters:

* **ComfyUI** (`/prompt`, `/history`, `/view`, `/upload/image`,
  `/system_stats`) with admin-registered workflow templates.
* **Internal inference API** (`/v1/image-generation`, `/v1/segmentation`,
  `/v1/depth`, `/v1/inpainting`, `/v1/i2v`, `/v1/health`), signed with
  an HMAC per request; a reference server lives in `inference-server/`
  (protocol layer tested; model handlers not yet run on a GPU).
* **Procedural** offline providers (our own code) so the whole pipeline runs
  without a GPU. Their output is marked as placeholder art until an editor
  approves it.

Which model serves which task comes from the **model registry** (`AiModel`).
The registry records the licence, whether commercial use is allowed, and
whether the model is approved for production. Generation is blocked for
models that aren't cleared, unless an admin override is recorded.

## 5. Workers and queues

| Queue | Job types | Runs on |
|---|---|---|
| `studio` | analysis, scripts, AI review, planning, voices, publish | CPU |
| `image-generation` | GENERATE_LAYER_ASSET | GPU |
| `segmentation` | GENERATE_MASK | GPU |
| `depth-generation` | GENERATE_DEPTH | GPU |
| `inpainting` | INPAINT_ASSET | GPU |
| `i2v` | RENDER_SHOT_I2V | GPU |
| `2.5d-render` | BUILD_SCENE_PACKAGE, RENDER_SHOT | CPU (multi-core) |
| `studio-render` (FFmpeg) | ASSEMBLE_MASTER_VISUAL, RENDER_LANGUAGE, RENDER_PACKAGE | CPU |
| `qc` | SHOT_QC, FINAL_QC | CPU |

GPU workers register themselves in `GpuWorker` and send heartbeats with
VRAM and running jobs. Scheduling is pull-based: each worker consumes only
the queues it is configured for, up to its slot count. VRAM is reported but
not yet used for placement. API processes never run inference.

## 6. Multilingual reuse

The visual track is rendered once per episode as a master visual. Every
language reuses it: only audio, subtitles, on-screen captions and the
localized disclosure are added per language. Shot durations come from
the longest language's speech per scene, so no language's voice is ever
sped up.

## 7. Journalistic safety

* The existing fact, safety and approval layers are unchanged.
* RESTRICTED scenes get substitute environments with no people.
* SENSITIVE scenes show people only as silhouettes.
* Minors are never drawn.
* Every cinematic video carries a localized "Visual reconstruction"
  disclosure.
* Publishing is blocked while any placeholder asset is unresolved, any
  asset comes from an uncleared model, or the disclosure is missing.
