# The 2.5D engine

`backend/src/studio/engine25d/` is a deterministic software renderer
written in TypeScript. It turns a **scene manifest** (layers, depth,
camera, characters, lights, particles, focus, effects) into video frames
and pipes them into FFmpeg. It needs no GPU. Every frame is a pure function
of `(manifest, seed, frame index)`, so a re-render is byte-identical, and
frames can be rendered in any order on any number of threads.

## Input: the scene manifest (`spec.ts`)

One zod schema (`sceneManifestSchema`) validates the whole manifest.

| Block | Contents |
|---|---|
| `canvas` | width, height, fps, durationSeconds |
| `layers[]` | `key`, `kind` (background / midground / character / prop / foreground), `zIndex`, `depth` (0 = far … 1 = near), `source` (image + optional mask/depth, or a character rig), `placement`, `motion`, `character`, `blend`, `lightResponse`, `castsShadow`, `silhouette`, `extraBlur` |
| `depth` | parallaxFar/Near (0.12 / 1.6), dollyFar/Near, fogDensity, fogCurve, displacement |
| `camera` | one of 15 moves (static, dolly_in/out, pan_left/right, tilt_up/down, orbit, tracking, push_in, pull_out, handheld, rack_focus, whip_pan, slow_zoom), keyframes, easing, intensity, focal length, shake, optional tracked layer |
| `environment` | weather + particle systems (15 types) |
| `lighting` | ambient + lights (sun, moon, streetlight, headlights, police, fire, neon, interior, window, train, generic) with flicker, pulse, movement, flare |
| `shadows`, `focus`, `effects`, `transition` | contact/projected shadows; aperture, focus depth or layer, rack; grain, vignette, bloom, flare, CA, motion blur, haze, grade; fade in/out |

## Frame pipeline (`frameRenderer.ts`)

For each frame `i` (`t = i / fps`):

1. **Performance.**
   * Layer motion: keyframes and oscillators.
   * Character performance (`characterMotion.ts`): pose, breathing, blinks,
     head turn, eye direction, sway, walk/run cycle, gestures, speech
     mouth, cloth/hair lag.
   * Walks feed `travelX` into camera tracking.
2. **Camera** (`camera.ts`): position, dolly/zoom, roll, orbit and shake at `t`.
   * The **cover-zoom solver** finds the smallest uniform zoom at which
     every `cover` layer fills the frame for the whole move, so edges are
     never revealed.
3. **Projection** (`depth.ts`).
   * Each layer's screen transform is `camera offset × parallaxFactor(depth)`,
     with dolly scaled by `dollyFactor(depth)`.
   * **Ground lock**: a standing layer uses the background depth at its
     feet, so it moves exactly like the floor under it (no foot sliding).
4. **Lights** (`lighting.ts`).
   * Lights are evaluated at `t`.
   * A 1/8-resolution light map is built.
   * A per-row `LightField` lets the compositor shade each pixel without
     per-pixel map lookups.
   * Characters and props use absolute lighting; pre-lit painted plates use
     relative lighting.
5. **Particles** (`particles.ts`): analytic, deterministic systems (no
   simulation state), each binned between the layers at its depth so rain
   falls *between* the train and the platform.
6. **Compose** back to front (`composite.ts`: premultiplied float RGBA,
   bilinear affine sampling, normal/multiply/screen/add).
   * **Displaced background plate**: a single painted image with a depth map
     gets per-pixel parallax.
     * The inverse mapping is solved on a 4-px grid, with 256-entry depth LUTs.
     * Depth-of-field blends between two blur levels.
     * Depth fog is applied.
   * **Image layers**: affine transform, light field, fog, DOF blur
     (`focus.ts` `BlurCache`, quantised so blurs are reused across frames),
     and horizontal motion blur from camera velocity.
   * **Rig layers** (`rigRenderer.ts`): cut-out parts posed per frame into a
     clipped offscreen buffer, then lit with a rim light and composited.
   * **Shadows**: a contact shadow under the feet, plus a projected shadow
     cast away from the key light.
7. **Post** (`effects.ts`): bloom, lens flare, chromatic aberration, haze,
   colour grade, vignette, film grain (pre-generated tile) and fades, then
   conversion to 8-bit sRGB.

## Rendering a shot (`shotRenderer.ts`)

* `renderShotToFile(scene, out, {width, height, fps, crf, preset, workers})`:
  * starts a pool of worker threads (`renderWorker.ts`) that share the
    decoded layer images through `SharedArrayBuffer`;
  * renders frames in parallel and writes them in order to FFmpeg
    (`rgb24` → libx264 yuv420p, `+faststart`).
* Cancellation: an `AbortSignal` stops the pool and kills FFmpeg
  (`RenderCancelledError`).
* `renderStillPng` renders one frame; the Shot Inspector preview and the demo stills use it.
* `ENGINE_VERSION` is part of the render cache key, so engine changes invalidate old renders.

## Performance (measured in this repository's container)

| Profile | Measured |
|---|---|
| 1080×1920 @ 30, 5 layers, 3 particle systems, 4 lights, rig character | 150 frames in **55.6 s on 4 vCPUs** (2.7 fps) |

That is ≈ 11 s of render time per second of output on a 4-vCPU host.

* A 90-second video therefore needs ≈ 17 minutes on one such host.
* 1,000 videos/month at that length is ≈ 280 render-host-hours a month.
* So two 4-vCPU render hosts (or one 8–16-core host) cover the target with headroom.

Unchanged shots are never re-rendered (render cache; see `render-pipeline.md`).

The admin **Production → Ops** page reports measured throughput for each
output profile (`metrics.ts`).

## Honest limits

* Characters are 2D cut-out rigs or single images. There is no 3D, and no
  body deformation beyond the rig's joints and simple whole-figure warps.
* Depth comes from a depth model or from the procedural prior. A wrong depth
  map produces visible stretching at large camera moves. The planner keeps
  move intensities moderate for that reason.
* Particles are stylised. Water, collisions and complex crowd physics are
  out of scope: the `MotionRequirementAnalyzer` routes those shots to
  optional local I2V, or keeps them calm.

## Try it

```bash
cd backend
npm run demo:railway -- --out ./demo-output             # 1080×1920 @ 30, 5 s
npm run demo:railway -- --out ./demo-output --preview   # 540×960, faster
```

The demo writes:

* `shot_001.mp4`
* three PNG stills
* `manifest.json`
* the generated procedural assets
