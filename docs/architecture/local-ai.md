# Local AI

Assets are generated by **self-hosted open-weight models** on our own GPUs.
No commercial image or video API is part of this pipeline. Three kinds of
provider implement the same interfaces (`backend/src/studio/localai/types.ts`):

| Interface | Procedural (built-in, CPU) | ComfyUI | Internal inference API |
|---|---|---|---|
| `LocalImageProvider.generateSceneAsset` | graphic-novel vector painter + character rigs | txt2img workflow (FLUX.1 schnell, SDXL) | `POST /v1/image-generation` |
| `LocalSegmentationProvider.segment` | alpha / key matte | — | `POST /v1/segmentation` (BiRefNet) |
| `LocalDepthProvider.estimate` | layer depth prior | depth workflow (Depth Anything V2 Small) | `POST /v1/depth` |
| `LocalInpaintingProvider.inpaint` | push–pull diffusion fill | — | `POST /v1/inpainting` (LaMa) |
| `LocalVideoProvider.generateShot` (optional) | — | Wan 2.1 I2V workflow | `POST /v1/i2v` |

## Choosing a provider (`localai/factory.ts`)

1. Each task resolves its model through the **model registry**
   (`models/modelRegistry.ts`, `resolveModel`):
   * Only enabled models are considered.
   * They are ranked default first, then by quality score.
   * In production, models that are not licence-cleared are skipped
     (see `docs/operations/model-registry.md`).
2. The model's `provider` field selects the adapter. Its `endpoint`
   overrides `COMFYUI_BASE_URL` / `INFERENCE_BASE_URL`.
3. Availability is health-checked (`/system_stats` or `/v1/health`) and
   cached for 30 s. If the GPU service is down, the stage falls back to the
   procedural provider:
   * The output is marked as a placeholder.
   * The fallback is logged on the job.
   * It never silently counts as model output.
4. Every result carries **provenance**: generator, model id and version,
   licence and commercial-use flag, seed, parameters, duration and GPU
   worker. It is stored on `AssetVersion`.

## ComfyUI adapter (`localai/comfyui/`)

* Workflows live in `backend/comfyui-workflows/*.json`, in **API format**
  with `{{placeholders}}`.
  * `fillTemplate` substitutes typed values.
  * It refuses to send a workflow with an unfilled placeholder.
* The client handles the rest:
  * uploads input images (`/upload/image`)
  * queues the prompt (`/prompt`)
  * polls `/history/<id>`, honouring cancellation and timeouts
  * downloads outputs (`/view`)
* Generation sizes are fitted to the model's pixel budget and rounded to
  multiples of 16 (`fitGenerationSize`).
* The workflow directory resolves for both `tsx` and compiled builds. Set
  `COMFYUI_WORKFLOW_DIR` to override it.

## Internal inference API (`localai/http/`, server in `inference-server/`)

Every job is signed:

```
Authorization:   Bearer <INFERENCE_API_KEY>
X-Atma-Job-Id:   <job id>
X-Atma-Timestamp: <unix seconds>
X-Atma-Signature: hex(HMAC-SHA256(INFERENCE_SIGNING_SECRET, "<timestamp>.<jobId>.<sha256hex(body)>"))
body: {"jobId", "model", "inputs": {name: base64}, "params": {...}}
→    {"outputs": {name: base64}, "model", "modelVersion", "durationMs", "gpuWorkerId", "metadata"}
```

* The server rejects:
  * a bad key or signature
  * timestamps more than ±300 s off
  * replayed signatures
  * a body `jobId` that differs from the header
  * models not on its allowlist
  * oversized bodies
* Error mapping in the client:
  * 401/403 → configuration error, not retried
  * 4xx → rejected
  * 429/5xx/timeouts → retried by the job runner with exponential backoff
* The reference server (Python/FastAPI) is in `inference-server/`.
  * Its auth and protocol layer is tested, including against this client
    over HTTP.
  * Its model handlers have **not** been run against real weights. See its
    README for the bring-up checklist.

## Endpoint policy (`localai/endpointPolicy.ts`)

GPU endpoints must not be reachable from the public internet. The backend
accepts an endpoint only in two cases:

* the host is local or private: `localhost`, RFC 1918, link-local, `*.internal`
  / `*.local`, or single-label service names such as `comfyui`;
* or it uses **HTTPS and an API key**.

Anything else is a configuration error. Secrets are read only from the
environment and are never stored in the database or returned by the API.

## Optional I2V

* I2V is off unless `LOCAL_I2V_ENABLED=true` **and** a licence-cleared
  VIDEO_GENERATION model is enabled.
* It is used only for shots where the analyzer selected `i2v` (or an editor
  forced it).
* The 2.5D engine renders the shot's first frame. The model animates 3–5 s
  from it.
* `conformClip` then fits the clip to the shot's resolution, fps and
  duration.
* On any failure the shot is rendered by the 2.5D engine instead. The
  fallback reason is stored on the render.
