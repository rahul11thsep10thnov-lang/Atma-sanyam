# DADU – Release readiness

Date: 2026-11-03, head `93b5615`. Verdict first: **DADU is not production-ready.** The product
runs end to end on the web export and the API and console are tested, but nothing has run on a
phone, no store build exists, and the legal and store artefacts for a children's app are not
written. The shortest path to a closed Android beta is at the end of this page.

## 5. Verdict

**No-go for production on both platforms.** Engineering is at a working, tested build; the
blockers are device verification, store builds, the legacy-asset strip, crash reporting, and the
legal and store artefacts a children's app must have.

## 6. Shortest path to a closed Android beta (internal testers, in order)

1. Choose the DADU bundle id and version (`app.json`, `eas.json`), replace Tame's privacy
   manifest entries, bump to 1.1.0. (ENG, half a day)
2. Strip the legacy Tame assets from the DADU build or move them behind a build-time flag so
   the beta install is under 25 MB. (ENG, one day)
3. Add crash reporting (Sentry) with child-safe scrubbing (no names, no content), and API uptime
   alerts. (ENG, one day)
4. Produce an EAS internal-distribution Android build and run the device protocol on one budget
   phone and one mid-range phone; fix anything below budget, especially scene frame rate. (ENG,
   two to three days)
5. Run the editorial workflow on the bundled English and Hindi content through the CMS (at least
   educational and safety review) and record approvals. (CONTENT, two to three days, parallel)
6. Write the DADU privacy policy, terms and parental consent notice; get DPDP sign-off on the
   consent method. (LEGAL, parallel)
7. `npm audit` in CI and dependency review. (ENG, hours)
8. Closed beta on Google Play internal testing with ten to twenty families; collect crash and
   screen-time data for two weeks before widening.

iOS follows the same list after the Android beta is stable, plus Apple Kids Category review and
the privacy labels.
